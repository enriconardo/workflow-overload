# Backlog

- **`integrate`: pull or merge requests on GitHub, GitLab and Bitbucket.** Today `integrate.sh` merges locally with `--no-ff` and refuses any other value. A project that integrates by PR/MR cannot use the plugin. The value is not a switch: the process is built on the local merge, and each forge needs its own tool (`gh`, `glab`, Bitbucket's API). To design first: where the metrics line goes, since it rides on the merge commit and a protected `main` takes no commit from the plugin; who checks the merge's result, today `check` on it, then the CI; where the last checkpoint is, the conversation or the PR's review; what happens to the journal, today dropped by the merge; whether squash and rebase merges are allowed, since squash erases the one-logical-change commits. Source: review of the config's responsibilities.
- **brainstorm: never run the explorer on a plainly S task.** `phases/brainstorm.md`, step 2, skips the explorer only for an S request "whose files you already know and have read", which at the start of a task is almost never: a docs-only backlog item ran it (about 70k weighted, a fifth of the task). On S the main agent reads the files anyway to change them, and finds the callers with `git grep`, so the explorer only adds a second reading and its report. New rule: explore only when the task may be L; a plainly S request reads its files itself. A task in doubt still explores, so the triage keeps its map; an S that turns L gets its map from `phases/l-plan.md`, which runs the explorer when no map is logged. Source: metrics of a run of S and L tasks.
